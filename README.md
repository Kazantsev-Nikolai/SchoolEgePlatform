# SchoolEgePlatform

## 🛠️ Технологический стек

Проект разрабатывается с использованием современного стека технологий:

- **Backend:** NestJS (TypeScript) — надёжный и масштабируемый фреймворк для создания серверных приложений.
- **Frontend:** Vue.js 
- **База данных:** PostgreSQL — мощная объектно-реляционная СУБД.
- **Дополнительно:**
  - **Docker** — для контейнеризации и упрощения развертывания.
  - **SonarQube Cloud** — для автоматического анализа качества и безопасности кода.
  - **GitHub Actions** — для CI/CD пайплайнов и автоматических проверок.
  
## 🚀 Рабочий процесс с Git

### 🌿 Именование веток

Все ветки создаются по следующему шаблону:

**Для нового функционала:**

feature/ws-<номер задачи>_<краткое описание>

*Пример:* `feature/ws-12_authentication_form`

**Для исправлений:**

fix/ws-<номер задачи>_<краткое описание>

*Пример:* `fix/ws-15_correct_validation_error`

---

### 📝 Именование переменных

- Никаких `l`, `a`, `massive` и прочих неинформативных названий.
- Имя переменной должно чётко отражать её назначение.
- ✅ **Хорошо:** `login`, `password`, `userEmail`, `isFormValid`
- ❌ **Плохо:** `l`, `p`, `arr`, `flag`

> **Примечание:** Если вы считаете, что переименование переменной в данном контексте неоправданно или непонятно как исправить — это можно и нужно обсудить с командой.

---

### 💬 Коммиты

Коммиты должны быть **частыми** и с **осмысленными сообщениями** на русском языке.

**Примеры хороших сообщений:**
- `Создала визуальную часть формы`
- `Сделала передачу логина и пароля на сервер`
- `Принятие с сервера данных`
- `Сделала валидацию полей`

---

### 🔀 Pull Request (PR)

1.  **Название:** формируется по шаблону задачи.
    *Пример:* `ws-12 Создала форму входа и регистрации`
2.  **Описание:** обязательно пишем, что именно было сделано в рамках задачи.
3.  **Проверки (Pipeline):**
    - Убедитесь, что все автоматические проверки пройдены и вы видите зелёные галочки.
    - Внимательно читайте замечания и предложения от линтеров и тестов, исправляйте их.

---

### 🌿 Стратегия ветвления

В проекте используется упрощённый Git Flow.

**Основные ветки:**

| Ветка | Назначение |
|-------|------------|
| `main` | **Production.** Содержит только стабильный, протестированный код, готовый к деплою на продакшен. |
| `develop` | **Разработка.** Ветка, в которой собирается весь новый функционал перед релизом. |

### 🛠️ Полезные команды Git

```bash
# Клонирование репозитория
git clone <url>

# Переключиться на существующую ветку
git switch main
git switch develop

# Создать новую ветку и сразу переключиться на неё
git switch -c feature/ws-12_authentication_form
git switch -c fix/ws-15_correct_validation_error

# Вернуться к предыдущей ветке (быстрое переключение туда-обратно)
git switch -

# Проверить, в какой ветке ты сейчас находишься
git branch
git status

# Добавить файлы в коммит
git add .                     # добавить все изменённые файлы
git add <имя_файла>           # добавить конкретный файл

# Создать коммит
git commit -m "Создала визуальную часть формы"

# Отправить ветку в удалённый репозиторий (первый раз)
git push -u origin feature/ws-12_authentication_form

# Отправить изменения, если ветка уже существует на сервере
git push

# Подтянуть изменения из основной ветки, пока работаешь в своей
git switch develop && git pull && git switch ветка в которой ведется разработка && git merge develop

# Отменить изменения в файле (если ещё не коммитила)
git restore <имя_файла>

# Удалить локальную ветку
git branch -d feature/ws-12_authentication_form
